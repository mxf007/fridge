## 0. 一句话与范围

玩家观察购物袋**栈顶**，把食材按类收进合适容量的冰箱格；不确定时先放**柜台**翻开下一层。格满封门。购物袋**每列只剩 1 个**时，若剩余食材按容量已经摆不满冰箱，直接失败，不必先把食材堆满柜台。

### 0.1 现行锁定（不要再改回）

| 锁定 | 说明 |
|------|------|
| 先选目标，再落子 | 点格/柜台空位设目标（不计步）→ 再点栈顶或柜台食材（成功才计步） |
| 禁止自动落格 | 禁止点食材后系统自动找格、自动进柜台 |
| 1–9 无关台 | `bufferEnabled = id >= 10`；不渲染、不可选、不可收 |
| 下层匿名 | 只显示栈顶种类 + 剩余层数；禁止颜色/轮廓/半透明泄露下层 |
| 柜台只在冰箱放不下时强制 | 第 10 关起，冰箱还有格子能收这件，就可以直接放。所有冰箱格都收不了时，才必须先放柜台 |
| 无拖拽 / 摇杆 / 倒计时 / 金币 / 体力 / 底导航 / BGM | — |
| 分享文案 | 失败拉新写「让好友也收这一层」，不要「请人看一眼」 |
| 效果图多余物 | 豆浆/豆腐/鸡蛋、Undo 英文、底栏图标：不做进关卡或 UI |

### 0.2 V1 做 / 不做

**做：** 栈顶选择、目标格收纳、容量与防拆分、柜台暂存、胜负、提示/撤销、失败分型续玩、个人最佳、分享拉新、冰箱成品图鉴。

**不做：** 养成、抽卡、体力、剧情、PVP、3D 漫游、从冰箱取出、柜台槽对倒、食物百科解锁、依次解锁冰箱格、下层染色剧透、好友排行、每日挑战（原型期）。

### 0.3 工程进度（文档维护用）

- 对局主场景 + `BoardState` + 第 **1–30** 关可玩链路已落地。  
- 第 7–30 关已按深栈顶规则重排：同列连续相同不超过 2，第 13 关起每列至少 3 层。19–30 的旧叠放不再冻结。  
- 第 1 / 4 / 7 关换格验收不过，禁止继续铺更后段关卡。

## 1. 玩家在干什么

每关：购物袋叠食材，只能看见并点击每列栈顶；冰箱有若干空格，默认选中最左空格。第 1–9 关不显示柜台。

结束：冰箱收齐 → 胜利（成品图 + 下一关）；无合法步 → 失败（按死法广告续玩或免费重开）。

**核心五拍：** 看栈顶与容量 → 直接锁格或暂存 → 翻开未知下一层 → 调整容量分配 → 连续封格。

| 关卡段 | 时长感 | 感觉 |
|--------|--------|------|
| 1–4 | 15–35 秒 | 点、换格、封格；不失败 |
| 5–7 | 25–50 秒 | 多列 + 下层未知 |
| 8–9 | 35–60 秒 | 混容量；第 9 关第一次可理解锁错 |
| 10–15 | 40–90 秒 | 柜台翻层；第 15 关阶段考 |
| 16–18 | 50–100 秒 | 新种类 / 深栈 / 大格诱惑 |
| 19–30 | 60–120 秒 | 新水果 / 五色 / Boss；见 §5.4 |

定位是**轻策略休闲**：首通偏松，难度靠决策复杂度后置；步数成绩服务重玩，不挡通关。

## 2. 操作（两种点击）

### 2.1 选目标（不计步）

- 点**冰箱格**或（第 10 关起）**柜台空位**设为当前目标。  
- 开局默认：最左空冰箱格。  
- 目标被封/占满：自动改选最左可收冰箱格；再没有且柜台已开 → 最左空柜台；再没有 → 无目标，点食材一律弹回。  
- 换目标不是一步。封格后的自动改选**不能代替**第 4、7 关换格教学。

### 2.2 落子（成功才 +1 步）

点**购物袋栈顶**，或（第 10 关起）点**柜台里已有食材**，飞向当前目标。

**冰箱格可收，仅当：**

1. 该格已锁定为该种类且未满；或  
2. 该格为空，**且**场上没有「同种且未满」的其它冰箱格（**防拆分**）。

**柜台空位可收：** 本关柜台已开且该槽为空。  
否则弹回，不计步，必须分因反馈（2.4）。

### 2.3 三种决策

| 决策 | 教关 |
|------|------|
| 点哪一列栈顶 | 第 5 关起 |
| 放进哪一个冰箱格 | 第 4 换格；第 8 尺寸；第 9 锁错 |
| 先存柜台再翻层 | **第 10 关登场**；有限探查资源，不是自动收容站 |

### 2.4 弹回反馈

横摆 80ms + Toast 1.2s。第一次说完整句；之后同关可只抖 + 闪格。

| 原因 | Toast | 同时 |
|------|--------|------|
| 种类不对 | 这格只收××（用锁定名；葡萄格写「葡萄」） | Sage 闪所有当前可收该食材的格 |
| 防拆分 | ××那格还没收满，不能新开一格 | 闪已有未满同种格 |
| 冰箱都放不下 | 冰箱放不下，先放到柜台 | 闪空柜台。只有没有任何冰箱格能收这件时才出现 |
| 没选目标 | 先点要放进的格子 | 闪最左可收冰箱格 |
| 目标已满/已封 | 这格收好了，换一格 | 自动改选后描边跳转 |

第 4、7 关第一次种类不对可用短句「换一格」。

## 3. 盘面与规则

### 3.1 三块区域

```
冰箱（竖格最多 4 个、同高；相同容量同外形。装不下的整组改成横屉，个数按宽度排，不写死。cap 仍只是 2/3/4）
购物袋（栈顶超过 4 个才两排，每排最多 4 列。只显示栈顶 + 层数）
柜台（第 10 关起 3 格；与冰箱一样是可选目标）
```

### 3.2 食材

本关出场 = `bags` 里出现的 id。硬约束按本关算，不按全池。

**1–17 关**只用前 6 种；**第 18 关起**才可写新水果 id。新水果彼此是真种类。不要食物解锁弹窗；图鉴是「收过的冰箱」。

| id | 名 | 投放 |
|----|----|------|
| milk | 牛奶 | 全程 |
| veg | 青菜 | 全程；与猕猴桃/西瓜/菠萝同关须另有第三色 |
| fruit | 苹果 | 第 5–17 关 |
| meat | 肉 | 第 12 关起 |
| sauce | 酱 | 第 16 关起；不与椰子同关 |
| leftover | 剩菜 | 第 21 关起；不与葡萄同关 |
| grape | 葡萄 | 第 18 关起；宜 2–3 件 |
| lemon | 柠檬 | 第 19 关起 |
| kiwi | 猕猴桃 | 第 20 关起 |
| pineapple | 菠萝 | 第 22 关起 |
| watermelon | 西瓜 | 第 25 关起 |
| coconut | 椰子 | 第 28 关起；不与酱同关 |

**互斥：** 葡萄×剩菜；椰子×酱；柠檬×菠萝；猕猴桃/西瓜/菠萝×青菜（本关无第三色时禁止）。

### 3.3 冰箱格

- `cap`：2 / 3 / 4，第 14 关底下那格是 5。可混用。外形见 `docs/今晚冰箱_UI设计.md`：短边 2 个座位、长边等于容量，横格是竖格转 90 度。第 1–11 关里容量 4 竖放；第 12 关起按能不能铺满决定朝向，容量 4 也可以倒放。相邻两关不用同一张摆放。  
- 空格第一件锁定种类。  
- 件数 = cap → **封格**。竖格与横屉都是浅灰门从右向左合上，右缘竖把手；不再接收，不腾成新空格。  
- 选中竖格或横屉：内腔变亮 + 淡蓝描边呼吸。已封格不能再选。  
- **不做**「填满 A 才能开 B」的依次解锁。

### 3.4 购物袋

- 列数组：下标 0 栈底，末项栈顶。  
- **只有栈顶显示种类并可点。** 下层中性托盘边 + 层数。  
- 移走栈顶后 160–220ms 翻层；动画中该列锁点击。  
- 列与列不阻挡（不做左右挡）。  
- **多排不强制：** 开局可见栈顶超过 4 个才前后两排，每排最多 4 列。12 件且栈顶不超过 4 个时用一排深栈。深列在后，开局定排后不跳动。  
- **第 7–30 关叠放：** 同一列从底到顶，相同食材最多连续 2 个。`奶,奶,奶` 不合法，`奶,奶,菜` 和 `奶,奶,菜,菜` 合法。深度 ≥ 2 的列至少两种，纯列 `奶,奶` 不合法。这是关卡数据约束，写在 `assertRedoLayout`，不放进第 1–6 关共用的 `assertLevel`（第 1 关仍是一列四杯奶）。  
- **第 10–30 关**开局每列深度 ≥ 2。**第 13–30 关**开局每列深度 ≥ 3。  
- 小件尽量放在栈顶，让玩家数得清该进哪一格。下层排列会撑爆信念预算时，不跑全排列，改用通关脚本和一条锁死脚本验收。

### 3.5 柜台

- 默认 3 格；广告 +1 上限 4。  
- 1–9 关闭。第 10 关第一次亮起。  
- 是目标位，不是自动收容：弹回时**不会**自动飞进柜台。  
- 价值：不立刻锁定冰箱容量，先翻开下一层。进/出柜台都计步。  
- **第 10 关起：** 冰箱还有空格，或已有同种未满格，这件食物就可以直接放进冰箱，不强制走柜台。只有所有冰箱格都收不了（种类不对、已经封上，或防拆分后也没有能收的格），才拒绝，原因 `need_buffer`，文案「冰箱放不下，先放到柜台」。  
- 正确路线可以不占柜台。锁进错误容量仍然会 `locked_out`。柜台用来在冰箱暂时放不下时把栈顶挪开。  
- 不做柜台槽对倒。

### 3.5.1 隐藏信息公平（锁定）

可见信息只有：冰箱容量/锁定/已填、栈顶种类与层数、柜台内容。

| 阶段 | 要求 |
|------|------|
| 1–4 | 不考隐藏信息 |
| 5–8 | 可隐藏下层，但任一合法可见落子仍可解 |
| 9 | 小容量那种食材的件数全在栈顶；至少一列深度 ≥ 2；存在一条看得见的锁错路线 |
| 10+ | 冰箱能收的栈顶可以直接进冰箱。存在不占柜台的安全路线。锁进错误容量会失败。下层排列撑爆信念预算的关，用通关脚本和锁死脚本验收，不跑全排列 |

提示只能返回可见安全动作。禁止用免费撤销/广告掩盖强制猜测。

### 3.6 胜负

**胜利：** bags 空且 buffer 空且已放食材均已封格离场。

**失败：** 不存在「换目标 + 点可点食材」的合法步。另外，**第 1–30 关统一**：**购物袋每列深度都是 1**（没有下层可翻）时，若某一格已定了种类但场上这种食材凑不满该格，或剩余各食材件数对不上剩余空格容量、已经不可能收齐，直接 `locked_out`，不用等柜台堆满。任一列深度仍 ≥2 时不做这条提前判定，柜台仍用来翻层。选错当前目标弹回 ≠ 失败。无步数上限、无倒计时。

| failReason | 文案 | 续玩 |
|------------|------|------|
| `buffer_full` | 柜台堆满了 | 仅当 +1 柜台后可解 → 本关柜台 +1 续玩 |
| `locked_out` | 这格锁错了 | 撤回到可解（上限约 8 步）并补满 3 次撤销 |

优先级：先验证 `buffer_full` 能否救；否则 `locked_out`。1–8 不应出失败结算；1–9 不应出 `buffer_full`。

**步数：** 成功落子 +1；选目标/无效点击不计。不影响胜负与下一关。记录首通与个人最佳。

`loseable`：1–8 必须 `false`；第 9 关起按关验证填写。

### 3.7 成绩（不挡首通）

| 结果 | 条件 | 用途 |
|------|------|------|
| 收好了 | 通关 | 解锁成品图与下一关 |
| 利落收纳 | `steps ≤ targetSteps` | 图鉴 Sage 章 |
| 完美收纳 | `steps == theoreticalMinSteps` | 图鉴 Walnut 章；重玩挑战 |

`targetSteps` = 全信息下界 + 隐藏信息试玩余量，**不能**直接等于上帝最优。提示/续玩不取消通关。

图鉴上的章晚于这些数字。`targetSteps` 还没写进关卡时，不显示利落或完美，也不用「收好了」占一枚章。写进之后，利落线必须出现在胜利卡或该关图鉴卡上。完美仍是更紧的一档，玩家要能看到自己对上的步数。

## 5. 关卡曲线

### 5.1 原则

- 每一段只教一个新概念。  
- 件数总和 = Σcap；种类数 ≤ 格数；每种数量可被若干 cap 子集加总凑出。  
- 启动校验 + 全信息可解；第 5 关起加可见信息审计。  
- **第 1 / 4 / 7 关换格不过，禁止继续铺后段。**

### 5.2 字段

```ts
type LevelDef = {
  id: number;
  title: string;       // 仅开发
  teach: string;
  trays: { cap: number }[];
  bags: string[][];    // 每列底→顶，末项可点
  buffer: number;      // 默认 3；1–9 逻辑关闭
  loseable: boolean;   // 1–8 必须 false
  targetSteps?: number;
};
// bufferEnabled = id >= 10
```

### 5.4 第 19–30 关（已落地）

设计目标：**决策复杂度递增**（列数/深度、混容量、新食材、假同色），**不加惩罚性机制**（倒计时/体力/失败扣分一律禁）。每关标注「难度类型 + 分享钩子」。具体 `bags` 以 `assets/scripts/game/level_XX.ts` 为准。

**叠放：** 件数、容量、食材、互斥保持下表。列深按 §3.4：第 13 关起每列至少 3 层，同列连续相同不超过 2。冰箱朝向按 UI 文档：相同容量同外形。第 30 关是 `8×6`：上排两只容量 3 横放加容量 2，下面三只容量 4 竖放，右下少两列。

**落关门禁（19–30，避免「一种一格连点」）：**

1. **禁止**整关玩法仅为「全格同 cap + 每种件数 = cap + 种类数 = 格数」（新色登场关尤其禁止）。
2. **新色登场关**须含 **混容量**，或至少一种食材件数无法单独占满某一格（须换格 / 柜台 / 锁错）。
3. 工程 `selfCheck` 含 `assertLevel`、`assertRedoLayout`、开局栈顶能进冰箱、成功路径不占柜台、waste 路径（`locked_out` 或 `buffer_full`）。全排列审计只在信念预算内跑；撑爆的关不跑。

| 关 | 教学 / 情绪 | 格(容量) | 列×深 | 种类 & 件数 | 柜台 | 可失败 | 分享 / 拉新钩子 |

### 5.5 关键学脚本（1 / 4 / 7 / 10）

**第 1 关：** 默认选中唯一格 → 点栈顶 ×4 → 封格 → 胜利。无柜台。还没赢过时，第一下落子前用手指贴图指向栈顶；第一杯飞进格子后收掉。不教换格。

**第 4 关：**

```json
{
  "id": 4,
  "trays": [{ "cap": 4 }, { "cap": 4 }],
  "bags": [
    ["veg", "veg", "veg", "milk"],
    ["milk", "milk", "milk", "veg"]
  ],
  "loseable": false
}
```

格 0 未满时青菜必须弹回；须先点格 1 再放。

**第 7 关：** 同结构缩小容量；不点第二格则青菜永远进不去。提示灯本关第一次出现且免费。

**第 10 关：** 第一次画柜台。栈顶能进容量 2 就直接放冰箱，不强迫第一件放柜台。水果或青菜放进容量 4 会锁死。只有所有冰箱格都收不了时，才提示「冰箱放不下，先放到柜台」。禁止写成「放不下就自动扔柜台」。不在本轮填写 `targetSteps`。

### 5.6 手感

- 飞入 0.18–0.28s；封格盖+轻震；弹回横摆 80ms + 分因 Toast；换目标描边 80ms。  
- 将失败：每列只剩 1 个且格子凑不满 / 件数对不上空格，或已经没有合法步 → `buffer_full` 闪柜台 / `locked_out` 闪凑不满的格 → 再出结算卡（居中）。

## 8. 图鉴（轻收集）

每关胜利一张**这一层的冰箱**。不是食物百科，也不做未收关的锁格墙。

- 按关解锁。成品按该关格子来排：格数、容量谁大谁小、竖格还是横屉，与对局同一套朝向。门心放这一格收进的食材图（已有 `food_*`）。
- 画面以首通封门为准。重玩只刷新最佳步数，不改这张图。
- 卡片上只有三样：这层冰箱、关号、一行状态。没有步数目标时，状态写最佳步数（旧档没有步数则写「已收」）。首通只在和最佳不同时，附在同一行。利落 / 完美见 §3.7，条件没落地之前不显示，也不留空位。
- 点已收卡「再收一次」，直接进该关开局。没有详情页。
- 已至少收过 1 关、且未满 30 时，列表末尾一只不能点的空框，只写「第 n+1 关」。没有锁。0 关时只显示空态文案。继续往前走仍用主页「开始收拾」。
- 不加成数值。
- 「图鉴 +1」只在首通，挂在胜利卡上。重玩已收关不挂。
- 主页文字链显示 `cleared / 30`。10 / 20 / 30 首次达成时触发 §7 里程碑，只弹一次。
- 按住已收卡约 500ms 分享这一张缩略（关号 + 步数）。手指滑动作废长按。
- 每日挑战、100+ 关回访：**上线盘再做**。原型 30 关只验规则。
