# 今晚冰箱 · 可开工玩法文档

工作标题：**今晚冰箱**  
品类：生活题材排序消除（Sort & Clear）  
平台：微信小游戏 · 竖屏 720×1280 · IAA 为主  
文档用途：按这份即可做 14 天可玩原型。工程在 `F:\fridge`，不要改 `blue_bean`。  
视觉：风格 **Night Fridge（暖夜厨房）**，见 `docs/今晚冰箱_UI设计.md` 与 `docs/ui_refs/`。

---

## 0. 一句话与非目标

玩家把买回来的食材，按类收进冰箱格子。格子满了就封上。柜台（缓冲）塞满且没有可收的菜，就失败。

**V1 不做：** 养成、抽卡、体力、剧情、实时 PVP、物理流体、3D 场景漫游、和星际扫扫乐混服。

**V1 只做：** 点选收纳、胜负结算、前 30 关、提示/撤销/加格广告、分享卡关、极简成品收集。

---

## 1. 玩家在干什么

每关开始：购物袋里叠着食材，冰箱里有几个空格。  
每关结束：要么冰箱收齐（胜利，留下一张「今晚的冰箱」成品图），要么柜台堆满（失败，可看广告救一次）。

单关目标时长：

| 关卡段 | 时长 | 感觉 |
|--------|------|------|
| 1–10 | 15–40 秒 | 学会，必过 |
| 11–20 | 40–80 秒 | 要想一步 |
| 21–30 | 60–120 秒 | 会卡，想看提示 |

---

## 2. 操作（只有一种）

**点按**，没有拖拽、没有双指、没有摇杆。

1. 只能点 **袋口最上面那一件**（被压住的点了会抖一下，不算步）。
2. 点中后自动飞向唯一合法去处，优先级：
   - 已有同类且未满的冰箱格
   - 否则：空的冰箱格（此格从此锁定为该种类）
   - 否则：柜台空位
   - 否则：无效，食材弹回
3. 从柜台点食材：同样按上面规则飞回冰箱（柜台不是终点）。

不需要玩家瞄准格子。去向由规则判定，保证 5 秒素材里「点一下、东西飞进冰箱」能看懂。

## 3. 盘面与规则

### 3.1 三块区域

```
┌─────────────────────┐
│  冰箱（终点格 2–5 个） │  每个格有容量，收满同类即封格
├─────────────────────┤
│  购物袋（2–6 列）     │  每列是栈，只能点栈顶
├─────────────────────┤
│  柜台缓冲（默认 3 格） │  临时堆，可再点回去
└─────────────────────┘
```

### 3.2 食材种类（V1 只用 6 种）

| id | 名 | 色 | 图标建议 |
|----|----|----|----------|
| milk | 牛奶 | 白 | 盒装奶 |
| veg | 青菜 | 绿 | 叶菜 |
| fruit | 水果 | 红 | 苹果 |
| meat | 肉 | 橙 | 肉块 |
| sauce | 酱 | 棕 | 瓶 |
| leftover | 剩菜 | 紫 | 碗 |

美术第一版允许纯色块 + 小图标。种类靠颜色，不靠字。

### 3.3 冰箱格

- 容量 `cap`：2 / 3 / 4（前 30 关不用 5+）。
- **先放先进**：一格放入第一种食材后，本格锁定该种类。
- 格内件数 = `cap` → **封格**：盖子扣上、短震动、计数 +1。封格里的食材离场，不再占用规则。
- 本关所有食材离场（袋空、柜台空、未封格也空）→ 胜利。

### 3.4 购物袋

- 每列是数组，下标 0 为栈底，末项为栈顶。
- 只有栈顶可点。
- 列与列之间 **不阻挡**（降低误触，前 30 关不做「左右挡」）。
- 难度来自 **叠放顺序** 和 **柜台格数**，不来自复杂几何。

### 3.5 柜台（缓冲）

- 默认 3 个空位，本关内可看广告 +1，上限 4。
- 柜台食材随时可再点，飞去合法冰箱格。
- 柜台满时，若所有栈顶都既进不了冰箱也进不了柜台 → **失败**。

### 3.6 胜负（写死）

**胜利：** `bags` 全空 且 `buffer` 全空 且 所有已放食材都已封格离场。

**失败：** 无任何合法点击（含柜台点击）。

**不失败的情况：** 还有一步可放进冰箱或柜台，哪怕很蠢。不要用倒计时。前 30 关无步数上限。

**步数：** 每次成功放进冰箱或柜台 +1，只用于结算展示和分享，不影响胜负。

## 4. 界面（一屏，无二级页打断对局）

```
[关卡 12/30]              [撤销 3] [提示]
        冰箱格（横向 2–5 个）
        购物袋（横向列）
        柜台 3 格
[暂停]
```

- 撤销、提示在对局内，点了立刻生效，不要弹半屏商店。
- 暂停：重开本关 / 回选关。重开不弹广告。
- 结算层才出现：再来 / 下一关 / 看广告多 1 格重试 / 分享。

## 5. 前 30 关曲线

### 5.1 设计原则

- **1–5 关不允许失败**（即使用户乱点，柜台也够用）。
- **6–10 关可以失败，但撤销 3 次足够自救。**
- **11 关起** 才会出现「必须先把 A 暂存，才能拿 B」。
- 每一段只教 **一个** 新概念，不要同一关叠两个新规则。
- 同类总数必须能被格子容量整除，避免死关。校验公式：

```
每种食材数量 % 该种类所用格子容量之和 == 0
且 所有种类数量之和 == 所有格子 cap 之和
```

关卡表用 JSON 配，运行时启动时跑一遍校验，配错直接报错，不要上线。

### 5.2 字段

```ts
type LevelDef = {
  id: number;           // 1–30
  title: string;        // 仅开发用
  teach: string;        // 本关只教什么
  trays: { cap: number }[];          // 冰箱格，初始全空
  bags: string[][];     // 每列从底到顶，末项可点
  buffer: number;       // 柜台格数，默认 3
  loseable: boolean;
};
```

种类用 3.2 的 `id`。

### 5.5 手感（比关卡更影响次留）

- 飞入时长 0.18–0.28s，缓出。
- 封格：盖子 + 轻震 + 短音效，30 关内不要烟花全屏。
- 无效点击：食材横摆 80ms，不要弹窗。
- 将失败时，柜台格先闪红 0.4s，再出结算。让玩家看清「是这里满了」。

## 6. 广告点（对局中只允许 3 个，结算后 1 个）

原则：广告是 **过关工具**，不是关卡的一部分。前 5 关 **零广告**。

| 点 | 何时 | 形式 | 给什么 | 限制 |
|----|------|------|--------|------|
| 撤销 | 对局内，免费 3 次用完后 | 激励视频 | 再给 3 次撤销 | 单关最多看 1 次 |
| 提示 | 对局内，第 8 关起出现入口 | 激励视频 | 高亮 1 个安全栈顶（或柜台件） | 单关 1 次；1–7 关不显示 |
| 加格 | 失败结算 | 激励视频 | 本关柜台 3→4，从失败盘面续玩，不清空 | 单关 1 次；1–5 关失败也应极少，若发生则直接重开 |
| 插屏 | 胜利结算点「下一关」之后 | 插屏 | 无 | 仅 10 关以后；两次插屏至少隔 2 关；从后台回前台不弹 |

**禁止：** 开局插屏、飞行动画中插屏、倒计时强迫看、不看广告就不能重开。重开永远免费。

提示算法（V1）：对每个可点对象模拟一步，若该步后「可解」（用简化检测：仍存在至少 1 个能进冰箱的动作，或缓冲未满），则标为安全。多个安全步时，优先「能直接进已锁定的同类格」。不要做完整求解器也可以先上，提示不准时再换。

## 7. 分享点（只做 2 个，都要能拉回访）

微信分享要带 **关卡号 + 种子**。点开的人进的是 **同一关**，不是主页。

| 点 | 触发 | 卡片 | 接收者进到哪 | 回访 |
|----|------|------|--------------|------|
| 卡关求助 | 失败结算主按钮「请人看一眼」 | 「第 N 关这层我收不进去了」+ 冰箱缩略图 | 直接进第 N 关，可玩 | 求助者次日可领 1 次免费提示（同一好友每天只算 1 次） |
| 收完炫耀 | 15、25、30 关胜利 | 「我把今晚的冰箱收好了，用了 X 步」 | 直接进同一关挑战更少步 | 写入本关「好友最佳步数」，自己再进这关时顶栏可见 |

不做：分享得体力、分享得金币、必须分享才能下一关。审核和留存都差。

开放数据域：V1 只排 **第 15 / 25 / 30 关最少步数**。不要做全球总榜。

## 8. 轻收集（回来的理由，不影响过关）

每关胜利生成一张 **冰箱成品图**（当前封格的颜色拼贴即可）。

- 图鉴按关卡号解锁，未解锁灰剪影。
- 主页入口：「我收过的冰箱 12/30」。
- **不加成** 撤销次数、不强过关。
- 30 关收齐给一个静态「第一台冰箱」徽章，用于分享图。

每日挑战（原型可后做，数据预留）：用日期作种子抽一关 11–20 的变体，记当日最少步。这是 D7 的主钩子，但 **14 天原型可以不做**。

## 9. 数据与校验

```ts
// 启动时跑
function assertLevel(l: LevelDef) {
  const items = l.bags.flat();
  const totalCap = l.trays.reduce((s, t) => s + t.cap, 0);
  if (items.length !== totalCap) throw new Error(`L${l.id} count`);
  // 每种数量必须能被「若干格的 cap」组合装下。
  // V1 简化：所有 tray.cap 相同则 每种数量 % cap === 0；
  // cap 混用时手检，并在关卡备注里写清分配。
}
```

存档（先 `sys.localStorage`，微信再换 `wx.setStorage`）：

```ts
type Save = {

```

## 11. 过关指标（不过就换题材，不在关卡上死磕）

找 **至少 8 个陌生人**（不要全是开发者）：

| 指标 | 合格 | 不合格就改什么 |
|------|------|----------------|
| 不讲解，5 秒内第一次点对 | ≥7/8 | 第 1 关和飞行反馈 |
| 第 5 关完成率 | 100% | 前 5 关仍太绕 |
| 第 10 关完成率 | ≥6/8 | 第 6–10 暂存教学 |
| 第 15 关完成率 | ≥4/8 | 11–15 难度，可加 1 免费提示 |
| 「还想再开」主观 | ≥5/8 | 封格爽感、失败归因 |
| 次日自己打开 | ≥3/8 | 先加每日一关，再谈买量 |

次留样本太小只作方向。真买量线仍是：**小流量试投后次留约 30%**。低于 25% 停投，先换生活题材（抽屉收纳 / 线材整理），规则可复用。

## 13. 立刻开工的第一件事

1. 新建空项目，画 1 个冰箱格、1 列牛奶、3 个柜台空位。
2. 点 4 次能封格并出「收好了」。
3. 再进第 7 关 JSON，确认「暂存」成立。

这三步通了，再铺关卡表。关卡不是第一天的事。
