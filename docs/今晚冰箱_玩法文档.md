# 今晚冰箱 · 可开工玩法文档

工作标题：**今晚冰箱**  
品类：生活题材排序消除（Sort & Clear）  
平台：微信小游戏 · 竖屏 720×1280 · IAA 为主  
文档用途：按这份即可做 14 天可玩原型。工程在 `F:\fridge`，不要改 `blue_bean`。  
视觉：风格 **Night Fridge（暖夜厨房）**，见 `docs/今晚冰箱_UI设计.md` 与 `docs/ui_refs/`。

**2026-09-19 修订：** 废除「点食材后系统自动找格」。自动落格会让柜台、锁错、大格诱惑全部失效。现规则为 **先选目标格（不计步），再点食材落子（计步）**。

**同日策划核对再订：** 1–9 关柜台关闭；弹回分因 + 闪合法格；第 4 关迷你换格；第 10 关柜台登场（不写「不用必败」）；第 11 关教选格不教做不到的错法；失败广告按死法发奖；提示从第 7 关出现（第一次免费）；分享是拉新不是代打。30 关只验规则，All-in 前要有每日或 100 关。

## 0. 一句话与非目标

玩家把买回来的食材，按类收进冰箱格子。格子满了就封上。没有合法落子就失败：可能是柜台堆满，也可能是格子锁错、剩下的食材没处放。

**V1 不做：** 养成、抽卡、体力、剧情、实时 PVP、物理流体、3D 场景漫游、从冰箱取出、柜台之间对倒、和星际扫扫乐混服。

**V1 只做：** 选格 + 点选收纳、胜负结算、前 30 关、提示/撤销、失败续玩（分型发奖）、分享拉新、极简成品收集。

## 1. 玩家在干什么

每关开始：购物袋里叠着食材，冰箱里有几个空格，默认选中最左空格。第 1–9 关不显示柜台。  
每关结束：要么冰箱收齐（胜利，留下一张「今晚的冰箱」成品图），要么无合法步（失败，按死法看广告续玩或免费重开）。

单关目标时长：

| 关卡段 | 时长 | 感觉 |
|--------|------|------|
| 1–10 | 15–40 秒 | 学会点、学会换格；会弹回，基本不会失败结算 |
| 11–16 | 40–80 秒 | 选哪一格开始有对错；等容量下仍难无解 |
| 17–20 | 40–80 秒 | 混容量，选错尺寸会失败 |
| 21–30 | 60–120 秒 | 会卡，想看提示 |

## 2. 操作（两种点击，没有拖拽）

### 2.1 选目标（不计步）

- 点 **冰箱格** 设为当前目标，该格出现冷光描边。
- **第 10 关起** 才显示柜台；点 **柜台空位** 同样设为目标。第 1–9 关柜台不渲染、不可选、不可收（逻辑层 `bufferEnabled = id >= 10`）。
- 开局默认：最左边的空冰箱格。
- 若当前目标被封格或被占满：自动改选「最左的可收冰箱格」；都没有且本关柜台已启用，则改选最左空柜台；再没有则无目标，点食材一律弹回。
- 换目标不是一步。
- 封格后的自动改选是为了手感，**不能代替换格教学**。换格必须在「格未满、栈顶换色、必弹回」的关里学会（第 4、7 关）。

### 2.2 落子（成功才 +1 步）

点 **购物袋栈顶**，或（第 10 关起）点 **柜台里已有的食材**，飞向当前目标。

**冰箱格可收，仅当：**

1. 该格已锁定为该种类，且未满；或  
2. 该格为空，**且** 场上没有「同种类且未满」的其它冰箱格。

第 2 条是 **防拆分**：同种未装满时，禁止再开一个空格放它。前几关因此不会「一格一个牛奶」后把青菜关在门外。

**柜台空位可收：** 本关 `bufferEnabled`，且该槽为空。  
**否则：** 食材弹回，不计步，不弹模态窗。必须有分因反馈（见 2.4）。

### 2.3 三种决策（谜题从这里来）

| 决策 | 何时 | 教关 |
|------|------|------|
| 点哪一列栈顶 | 多列都有可点的顶 | 第 5 关起（第 4 关先把换格钉死） |
| 放进哪一个冰箱格 | 格未满、栈顶换色会弹回 | **第 4 关迷你换格**；第 7 关试金石；第 17 关尺寸 |
| 先存进柜台 | 本关柜台已亮，栈顶暂时不该进已选格 | **第 10 关登场**。等容量很难「不用柜台就无解」，不写必败；第 14 关用柜台更少换格；混容量（17–18）才可能出现「不暂存会锁死」 |

**不要做：** 双指、拖拽、瞄准飞行、从冰箱把食材拿出来。

### 2.4 弹回反馈（必须分因，不能只抖）

同一套横摆 80ms，叠 1.2s Toast。第一次触发该因时说完整句；之后同关可只抖 + 闪格。

| 原因 | Toast | 同时做 |
|------|--------|--------|
| 种类不对 | 这格只收牛奶（用当前格锁定的名） | Sage 闪一下 **所有当前可收该食材的格**（只提示，不代点） |
| 防拆分 | 牛奶那格还没收满，不能新开一格 | 闪已有的未满同种格 |
| 没选目标 | 先点要放进的格子 | 闪最左可收冰箱格 |
| 目标已满/已封 | 这格收好了，换一格 | 自动改选后描边跳过去 |
| 柜台未开放 | 不出现（点不到） | — |

第 4、7 关第一次「种类不对」可改用更短句「换一格」。不要用同一个「放不进去」应付三种规则。

## 3. 盘面与规则

### 3.1 三块区域

```
┌─────────────────────┐
│  冰箱（终点格 2–5 个） │  每个格有容量，收满同类即封格
├─────────────────────┤
│  购物袋（2–6 列）     │  每列是栈，只能点栈顶
├─────────────────────┤
│  柜台缓冲（第 10 关起 3 格）│  与冰箱格一样是「目标」，可再点回去
└─────────────────────┘
```

### 3.2 食材种类（V1 只用 6 种）

| id | 名 | 色 | 图标建议 |
|----|----|----|----------|
| milk | 牛奶 | 白 | 盒装奶 |
| veg | 青菜 | 绿 | 叶菜 |
| fruit | 水果 | 红 | 苹果 |
| meat | 肉 | 橙 | 肉块 |
| sauce | 酱 | 棕 | 瓶 |
| leftover | 剩菜 | 紫 | 碗 |

种类靠颜色 + 造型，不靠字。肉与酱必须造型不同（橙/棕相邻，防色弱）。

### 3.3 冰箱格

- 容量 `cap`：2 / 3 / 4（前 30 关不用 5+）。同一关可以混用不同 cap。
- **先放先进：** 空格放入第一件后，本格锁定该种类。
- 格内件数 = `cap` → **封格：** 该格冰箱门合上、短震动。封格后该格不再接收，也不腾成新空格。
- 封格里的食材离场，不再参与规则，只留在图鉴拼贴里。

### 3.4 购物袋

- 每列是数组，下标 0 为栈底，末项为栈顶。
- 只有栈顶可点。被压住的点了会抖，不算步。
- 列与列之间 **不阻挡**（前 30 关不做「左右挡」）。

### 3.5 柜台

- 默认 3 个空位，本关内可看广告 +1，上限 4。
- **第 1–9 关关闭。** 不画木底板、不可点、食材不能进。避免第 1 关把牛奶放到盘子上、学会错误模型。
- **第 10 关第一次亮起**（含木底板 + 3 方盘 +「柜台 0/3」）。亮起时不自动把目标改到柜台。
- 柜台是目标位，不是自动收容站：点食材 **不会** 在冰箱拒收时自动飞进柜台。弹回时可闪柜台（若本关已启用且该食材可进空槽）。
- 柜台上的食材再点一次，飞向当前目标（通常是冰箱格）。
- V1 不做柜台槽对倒。要把 A 槽的菜换到 B 槽：先选冰箱或只能保持原槽（进阶再做）。
- 先选格规则下，等容量 + 防拆分 + 种类数 ≤ 格数时，**柜台往往不是通关所必需**，只是少换格、翻开下面。教学句必须和求解器一致，禁止写「不存就必败」除非所有解的 `minBufferUsed >= 1`。

### 3.6 胜负（写死）

**胜利：** `bags` 全空 且 `buffer` 全空 且 所有已放食材都已封格离场。

**失败：** 无任何合法落子（购物袋栈顶和柜台食材，对当前可选目标都不合法；且没有可通过「换目标」变成合法的组合）。判定失败前，引擎必须扫一遍：是否存在「换一个目标 + 点一个可点食材」的合法步。只有全部没有，才失败。

失败结算必须带 `failReason`：

| `failReason` | 玩家看见的原因 | 激励续玩给什么 |
|--------------|----------------|----------------|
| `buffer_full` | 柜台堆满了 | 本关柜台 +1，从失败盘面续玩 |
| `locked_out` | 格子锁错了，剩下的收不进去 | **撤回至最近可解**（等价于连撤直到求解器判可解，上限 8 步）；并补满 3 次撤销 |

禁止一律发「多一格」：锁死盘面加一格盘子修不好，看完广告还是死。  
1–9 关没有柜台，不应出现 `buffer_full`。1–16 关不应出现失败结算。

**因此：** 只是当前选中格不对，不算失败，弹回即可。玩家换格后再点。

**不失败：** 还有一步可放进某个冰箱格或某个空柜台。不要用倒计时。前 30 关无步数上限。

**步数：** 每次成功落子 +1（进冰箱或进柜台都算）。只用于结算和分享，不影响胜负。

**`loseable` 字段：** 仅标注「本关是否预期会打出失败结算」。不能代替规则，引擎不写死禁止失败。

- **1–16 关** 等容量 + 防拆分，结构上很难无解。字段填 `false`。乱点 = 弹回，不是失败。不要按这些关收失败广告。
- **17 关起** 混容量，锁错尺寸可以无解。字段填 `true`。
- 若 1–16 打出了失败结算，当 bug 查（例如柜台过早启用）。

## 4. 界面（一屏，无二级页打断对局）

```
[关卡 12/30]              [撤销 3] [提示]
        冰箱格（横向 2–5 个，选中格有描边）
        购物袋（横向列）
        柜台 3 格（第 10 关起；选中空位同样描边）
```

- 撤销、提示在对局内，点了立刻生效，不要弹半屏商店。
- 提示入口：**第 7 关起显示**。第 7 关第一次免费；第 8 关起看激励视频。1–6 关不显示。
- 暂停：点左上关卡号，出 重开本关 / 回主页。重开不弹广告。
- 结算层才出现：下一关 / 按死法续玩的激励按钮 / 「让好友也收这一层」/ 分享步数。
- 当前目标必须一眼能看出（描边 + 槽内冷光），否则换格教学不成立。

## 5. 前 30 关曲线

### 5.1 设计原则

- **第 1 关完全不能失败**（1 种、1 格）。柜台关闭。
- **2–5 关：** 等容量、每种刚好一格；有防拆分。乱点最多弹回。第 2 关「左奶右菜」只热身，**不要当成换格教学**（位置对应会让人一路点过去）。**第 4 关迷你换格**（格未满、栈顶换色、必弹回）。不要在这一段放混容量。
- **6–9 关：** 加深混叠和小格封格。柜台仍关闭。`loseable: false`。
- **第 10 关：** 柜台第一次亮起。教「弹回后可以点柜台」。等容量下往往不用柜台也能过，**教学句不得写成必败**。脚本带一次柜台操作即可。
- **11–16 关：** 选空格开始有讲究。防拆分会挡住「给未满种类再开一格」，第 11 关教的是 **弹回了就去点空格或已有同种格**，不是「做出锁死」。`loseable: false`。
- **17 关起：** 混容量，选错尺寸会失败。`loseable: true`。第 18 关大格在左（默认目标是诱惑）；第 17 关小格在左（默认更安全）。
- 每一段只教 **一个** 新概念。
- 做关硬约束：

```
所有种类数量之和 == 所有格子 cap 之和
种类数 <= 格数
对每个种类：存在一种把若干格子分给它的方案，使这些格子 cap 之和 == 该种类数量
```

等容量时退化为：每种数量 % cap == 0，且 种类数 <= 格数。

关卡表用 JSON。启动时跑校验；**另外跑求解器**：至少存在一条合法解。配错直接报错，不要上线。  
第 10、14、18 关额外打日志：`minBufferUsed`（所有解里，进过柜台的最少次数）。第 10 关不要求 ≥1；第 14 关目标是最优解用柜台；第 18 关若做得到「所有解 ≥1」再把教学写成暂存，否则只写大格诱惑。

### 5.2 字段

```ts
type LevelDef = {
  id: number;           // 1–30
  title: string;        // 仅开发用
  teach: string;        // 本关只教什么
  trays: { cap: number }[];   // 冰箱格，初始全空
  bags: string[][];     // 每列从底到顶，末项可点
  buffer: number;       // 柜台格数，默认 3；1–9 关逻辑上仍为 3 但不启用
  loseable: boolean;    // 是否预期失败结算；1–16 必须 false
};
// bufferEnabled = id >= 10
```

种类用 3.2 的 `id`。

### 5.4 第 1、4、7、10、11 关示例（含逐步脚本）

**第 1 关 — 只会点**

```json
{
  "id": 1,
  "title": "先把牛奶收进去",
  "teach": "点最上面的，飞进已选中的格",
  "trays": [{ "cap": 4 }],
  "bags": [["milk", "milk", "milk", "milk"]],
  "buffer": 3,
  "loseable": false
}
```

脚本：默认选中格 0 → 点栈顶 ×4 → 封格 → 胜利。无换格。**柜台不显示。** 验收：点屏幕下方不应出现方盘。

**第 4 关 — 迷你换格（第 7 关之前先钉一次）**

```json
{
  "id": 4,
  "title": "格没满也会换色",
  "teach": "种类不对会弹回，先点另一个格子",
  "trays": [{ "cap": 4 }, { "cap": 4 }],
  "bags": [
    ["veg", "veg", "veg", "milk"],
    ["milk", "milk", "milk", "veg"]
  ],
  "buffer": 3,
  "loseable": false
}
```

脚本：

1. 默认选中格 0。点列 A 顶 `milk` → 进格 0，锁奶（1/4，**未封**）。  
2. 点列 B 顶 `veg` → 弹回 + Toast「换一格」+ 闪格 1。  
3. 点格 1，再点列 B `veg` → 进格 1，锁菜。

### 5.5 手感

- 飞入时长 0.18–0.28s，缓出。
- 封格：盖子 + 轻震 + 短音效，不要全屏烟花。
- 无效点击：食材横摆 80ms + 分因 Toast 1.2s（见 2.4），不弹模态。
- 换目标：描边 80ms 内切过去，不要闪全屏。
- 将失败时：先确认无合法步；`buffer_full` 则柜台闪 Coral 0.4s；`locked_out` 则锁死的冰箱格闪 Coral，再出结算。

## 6. 广告点（对局中只允许 3 个，结算后 1 个）

原则：广告是 **过关工具**，不是关卡的一部分。前 5 关 **零广告**。1–16 关不要指望失败激励，主广告点是提示（第 7 关免费一次，第 8 关起看视频）和撤销用尽。

| 点 | 何时 | 形式 | 给什么 | 限制 |
|----|------|------|--------|------|
| 撤销 | 对局内，免费 3 次用完后 | 激励视频 | 再给 3 次撤销 | 单关最多看 1 次 |
| 提示 | 对局内，**第 7 关起**出现入口 | 第 7 关第一次免费；其后激励视频 | 高亮 1 个安全目标格 + 1 个该点的食材 | 单关 1 次；1–6 关不显示 |
| 失败续玩 | 失败结算 | 激励视频 | **按 `failReason`：** `buffer_full` → 柜台 3→4 续玩；`locked_out` → 撤回到可解并补 3 次撤销 | 单关 1 次；1–16 关若误触发则直接重开、打日志 |
| 插屏 | 胜利结算点「下一关」之后 | 插屏 | 无 | 仅 10 关以后；两次插屏至少隔 2 关；从后台回前台不弹 |

**禁止：** 开局插屏、飞行动画中插屏、倒计时强迫看、不看广告就不能重开。重开永远免费。  
**禁止：** 锁死盘面只给「多一格继玩」。

提示算法（V1）：枚举「选目标 T + 点食材 I」，模拟一步后若求解器仍判可解，则该步安全。多个安全步时，优先「放进已锁定的同类格」。提示必须同时指出格和食材，只闪食材不够。已无解时提示不可用，Toast「这一步已经收不回去了，点撤销」。
