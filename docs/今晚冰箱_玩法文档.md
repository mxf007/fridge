## 0. 一句话与范围

玩家观察购物袋**栈顶**，把食材按类收进合适容量的冰箱格；不确定时先放**柜台**翻开下一层。格满封门。所有可见食材都没有合法去处时失败。

### 0.1 现行锁定（不要再改回）

| 锁定 | 说明 |
|------|------|
| 先选目标，再落子 | 点格/柜台空位设目标（不计步）→ 再点栈顶或柜台食材（成功才计步） |
| 禁止自动落格 | 禁止点食材后系统自动找格、自动进柜台 |

| 无拖拽 / 摇杆 / 倒计时 / 金币 / 体力 / 底导航 / BGM | — |
| 分享文案 | 失败拉新写「让好友也收这一层」，不要「请人看一眼」 |
| 效果图多余物 | 豆浆/豆腐/鸡蛋、Undo 英文、底栏图标：不做进关卡或 UI |

## 1. 玩家在干什么

每关：购物袋叠食材，只能看见并点击每列栈顶；冰箱有若干空格，默认选中最左空格。第 1–9 关不显示柜台。

结束：冰箱收齐 → 胜利（成品图 + 下一关）；无合法步 → 失败（按死法广告续玩或免费重开）。

**核心五拍：** 看栈顶与容量 → 直接锁格或暂存 → 翻开未知下一层 → 调整容量分配 → 连续封格。

| 关卡段 | 时长感 | 感觉 |
|--------|--------|------|
| 1–4 | 15–35 秒 | 点、换格、封格；不失败 |
| 5–7 | 25–50 秒 | 多列 + 下层未知 |
| 8–9 | 35–60 秒 | 混容量；第 9 关第一次可理解锁错 |
| 10–15 | 40–90 秒 | 柜台翻层；第 15 关阶段考 |
| 16–18 | 50–100 秒 | 新种类 / 深栈 / 大格诱惑 |
| 19–30 | 60–120 秒 | 新水果 / 五色 / Boss；见 §5.4 |

定位是**轻策略休闲**：首通偏松，难度靠决策复杂度后置；步数成绩服务重玩，不挡通关。

## 2. 操作（两种点击）

### 2.1 选目标（不计步）

- 点**冰箱格**或（第 10 关起）**柜台空位**设为当前目标。  
- 开局默认：最左空冰箱格。  
- 目标被封/占满：自动改选最左可收冰箱格；再没有且柜台已开 → 最左空柜台；再没有 → 无目标，点食材一律弹回。  
- 换目标不是一步。封格后的自动改选**不能代替**第 4、7 关换格教学。

### 2.2 落子（成功才 +1 步）

点**购物袋栈顶**，或（第 10 关起）点**柜台里已有食材**，飞向当前目标。

**冰箱格可收，仅当：**

1. 该格已锁定为该种类且未满；或  
2. 该格为空，**且**场上没有「同种且未满」的其它冰箱格（**防拆分**）。

**柜台空位可收：** 本关柜台已开且该槽为空。  
否则弹回，不计步，必须分因反馈（2.4）。

### 2.3 三种决策

| 决策 | 教关 |
|------|------|
| 点哪一列栈顶 | 第 5 关起 |
| 放进哪一个冰箱格 | 第 4 换格；第 8 尺寸；第 9 锁错 |
| 先存柜台再翻层 | **第 10 关登场**；有限探查资源，不是自动收容站 |

### 2.4 弹回反馈

横摆 80ms + Toast 1.2s。第一次说完整句；之后同关可只抖 + 闪格。

| 原因 | Toast | 同时 |
|------|--------|------|
| 种类不对 | 这格只收××（用锁定名；葡萄格写「葡萄」） | Sage 闪所有当前可收该食材的格 |
| 防拆分 | ××那格还没收满，不能新开一格 | 闪已有未满同种格 |
| 没选目标 | 先点要放进的格子 | 闪最左可收冰箱格 |
| 目标已满/已封 | 这格收好了，换一格 | 自动改选后描边跳转 |

第 4、7 关第一次种类不对可用短句「换一格」。

## 3. 盘面与规则

### 3.1 三块区域

```
冰箱（2–5 格，各有 cap）
购物袋（2–6 列栈；只显示栈顶 + 层数）
柜台（第 10 关起 3 格；与冰箱一样是可选目标）
```

### 3.2 食材

本关出场 = `bags` 里出现的 id。硬约束按本关算，不按全池。

**1–17 关**只用前 6 种；**第 18 关起**才可写新水果 id。新水果彼此是真种类。不要食物解锁弹窗；图鉴是「收过的冰箱」。

| id | 名 | 投放 |
|----|----|------|
| milk | 牛奶 | 全程 |
| veg | 青菜 | 全程；与猕猴桃/西瓜/菠萝同关须另有第三色 |
| fruit | 苹果 | 第 5–17 关 |
| meat | 肉 | 第 12 关起 |
| sauce | 酱 | 第 16 关起；不与椰子同关 |
| leftover | 剩菜 | 第 21 关起；不与葡萄同关 |
| grape | 葡萄 | 第 18 关起；宜 2–3 件 |
| lemon | 柠檬 | 第 19 关起 |
| kiwi | 猕猴桃 | 第 20 关起 |
| pineapple | 菠萝 | 第 22 关起 |
| watermelon | 西瓜 | 第 25 关起 |
| coconut | 椰子 | 第 28 关起；不与酱同关 |

**互斥：** 葡萄×剩菜；椰子×酱；柠檬×菠萝；猕猴桃/西瓜/菠萝×青菜（本关无第三色时禁止）。

### 3.3 冰箱格

- `cap`：2 / 3 / 4（不用 5+）。可混用。  
- 空格第一件锁定种类。  
- 件数 = cap → **封格**（灰门合上）；不再接收，不腾成新空格。  
- **不做**「填满 A 才能开 B」的依次解锁。

### 3.4 购物袋

- 列数组：下标 0 栈底，末项栈顶。  
- **只有栈顶显示种类并可点。** 下层中性托盘边 + 层数。  
- 移走栈顶后 160–220ms 翻层；动画中该列锁点击。  
- 列与列不阻挡（不做左右挡）。

### 3.5 柜台

- 默认 3 格；广告 +1 上限 4。  
- 1–9 关闭。第 10 关第一次亮起。  
- 是目标位，不是自动收容：弹回时**不会**自动飞进柜台。  
- 价值：不立刻锁定冰箱容量，先翻开下一层。进/出柜台都计步。  
- 不做柜台槽对倒。

### 3.5.1 隐藏信息公平（锁定）

可见信息只有：冰箱容量/锁定/已填、栈顶种类与层数、柜台内容。

| 阶段 | 要求 |
|------|------|
| 1–4 | 不考隐藏信息 |
| 5–8 | 可隐藏下层，但任一合法可见落子仍可解 |
| 9 | 全部深度 1；失败只能来自看得见的容量选择 |
| 10+ | 每个可见盘面至少一个不依赖下层身份的安全动作；`maxBufferNeeded ≤ 3` |

提示只能返回可见安全动作。禁止用免费撤销/广告掩盖强制猜测。

### 3.6 胜负

**胜利：** bags 空且 buffer 空且已放食材均已封格离场。

**失败：** 不存在「换目标 + 点可点食材」的合法步。选错当前目标弹回 ≠ 失败。无步数上限、无倒计时。

| failReason | 文案 | 续玩 |
|------------|------|------|
| `buffer_full` | 柜台堆满了 | 仅当 +1 柜台后可解 → 本关柜台 +1 续玩 |
| `locked_out` | 这格锁错了 | 撤回到可解（上限约 8 步）并补满 3 次撤销 |

优先级：先验证 `buffer_full` 能否救；否则 `locked_out`。1–8 不应出失败结算；1–9 不应出 `buffer_full`。

**步数：** 成功落子 +1；选目标/无效点击不计。不影响胜负与下一关。记录首通与个人最佳。

`loseable`：1–8 必须 `false`；第 9 关起按关验证填写。

### 3.7 成绩（不挡首通）

| 结果 | 条件 | 用途 |
|------|------|------|
| 收好了 | 通关 | 解锁成品图与下一关 |
| 利落收纳 | `steps ≤ targetSteps` | 图鉴 Sage 章 |
| 完美收纳 | `steps == theoreticalMinSteps` | 图鉴 Walnut 章；重玩挑战 |

`targetSteps` = 全信息下界 + 隐藏信息试玩余量，**不能**直接等于上帝最优。提示/续玩不取消通关。

## 4. 对局界面要素

```
[第 N 关]     [撤销] [提示]
      冰箱格（选中有描边）
      购物袋列
      柜台（第 10 关起）
```

## 5. 关卡曲线

### 5.1 原则

- 每一段只教一个新概念。  
- 件数总和 = Σcap；种类数 ≤ 格数；每种数量可被若干 cap 子集加总凑出。  
- 启动校验 + 全信息可解；第 5 关起加可见信息审计。  
- **第 1 / 4 / 7 关换格不过，禁止继续铺后段。**

### 5.2 字段

```ts
type LevelDef = {
  id: number;
  title: string;       // 仅开发
  teach: string;
  trays: { cap: number }[];
  bags: string[][];    // 每列底→顶，末项可点
  buffer: number;      // 默认 3；1–9 逻辑关闭
  loseable: boolean;   // 1–8 必须 false
  targetSteps?: number;
};
// bufferEnabled = id >= 10
```

### 5.4 第 19–30 关（策划草案，逐关落 JSON 前须过求解器与可见信息审计）

设计目标：**决策复杂度递增**（列数/深度、混容量、新食材、假同色），**不加惩罚性机制**（倒计时/体力/失败扣分一律禁）。每关标注「难度类型 + 分享钩子」，`bags` 顺序在落地阶段手填，不允许一次性生成 12 个 JSON。

**落关门禁（19–30，避免「一种一格连点」）：**

1. **禁止**整关玩法仅为「全格同 cap + 每种件数 = cap + 种类数 = 格数」（新色登场关尤其禁止）。
2. **新色登场关**须含 **混容量**，或至少一种食材件数无法单独占满某一格（须换格 / 柜台 / 锁错）。
3. 工程 `selfCheck` 除 `assertLevel` + `auditVisibleInformation` 外，须含 **成功路径 + waste 路径**（`locked_out` 或 `buffer_full`，不能只有 `wrong_kind` 弹回）。

数学复核（落 JSON 前每关再跑一遍）：
- Σ件数 == Σcap（19=12, 20=15, 21=13, 22=12, 23=12, 24=12, 25=16, 26=15, 27=12, 28=13, 29=15, 30=20）
- 每种数量 ∈ 若干 cap 子集和
- 种类数 ≤ 格数
- 互斥：无葡×剩、椰×酱、柠×菠、菠/西/猕×菜（无第三色时）冲突

节奏原则：
- 20/30 图鉴集齐 与 25 分享步数**错开**，避免同层撞钩子。
- 23、27 是有意让 `locked_out` 高发 → 拉新最自然。
- 24、26 是「柜台救活」样板 → `buffer_full` +1 广告转化最高。
- 每关**至少引入一种新色或新组合**，避免图鉴 30 张视觉重复。

### 5.5 关键学脚本（1 / 4 / 7 / 10）

**第 1 关：** 默认选中唯一格 → 点栈顶 ×4 → 封格 → 胜利。无柜台。

**第 4 关：**

```json
{
  "id": 4,
  "trays": [{ "cap": 4 }, { "cap": 4 }],
  "bags": [
    ["veg", "veg", "veg", "milk"],
    ["milk", "milk", "milk", "veg"]
  ],
  "loseable": false
}
```

格 0 未满时青菜必须弹回；须先点格 1 再放。

**第 7 关：** 同结构缩小容量；不点第二格则青菜永远进不去。提示灯本关第一次出现且免费。

**第 10 关：** 第一次画柜台。教学路径：点柜台空位 → 点不确定栈顶 → 翻层 → 再选合适冰箱格取回。禁止写成「放不下就自动扔柜台」。

### 5.6 手感

- 飞入 0.18–0.28s；封格盖+轻震；弹回横摆 80ms + 分因 Toast；换目标描边 80ms。  
- 将失败：确认无合法步 → `buffer_full` 闪柜台 / `locked_out` 闪锁死格 → 再出结算卡（居中）。

## 6. 广告（对局中 ≤3，结算后 1）
